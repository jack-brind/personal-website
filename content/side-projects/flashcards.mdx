# Building a tool to learn

At the end of 2024, I decided to start learning JavaScript. I was already proficient with HTML and CSS, but I wanted my prototypes to come to life and encounter the reality of a browser, and to do that I would need to be able to write JavaScript and, eventually, React code.

I signed up for Jonas Schmedtmann's [JavaScript course](https://www.udemy.com/share/101Wfe3@r4EkOsfS64doh_MjK1dAV6IlUlc78O50WbdB9F3U3W10qmjsNWkYE23tpm9PsvceyA==/) on Udemy. Early on, things were clicking like variables, conditionals and operators. But as the course progressed, more abstract concepts started to creep in and I found myself struggling to retain things I'd learned a few weeks earlier.

I came across a [blog post](https://www.joshwcomeau.com/blog/how-to-learn-stuff-quickly/) by Josh W Comeau on how to learn things quickly. He uses a physical Leitner box with flashcards to regularly review and retain knowledge. That inspired Flashcards and became a very effective way to absorb complex programming concepts and steer me away from _tutorial hell_.

# Scoping out the initial version

The app is fairly straightforward. Tips are written in Markdown, grouped into categories, and served randomly from whichever category you select.

I designed it to be mobile-first, since flashcards made the most sense as something I could quickly pull up anywhere. I added a `manifest.json` to enable PWA functionality and have it installed on my home screen with a native feel.

The app wouldn't just be for JavaScript and React either. Although I am comfortable with HTML and CSS, there are still many techniques that I am unfamiliar with that I'd like to learn, for example animations and accessibility. I would also like to learn things like Typescript and Next.js in the future, so the system needed to scale to support more topics over time.

For parsing Markdown I used [marked](https://github.com/markedjs/marked), which has worked well. Code snippets are currently images generated with a [Raycast tool](https://www.ray.so/) which is not ideal, but good enough for now.

# The present and the future of Flashcards

Writing the tips in my own words, using examples from my own life such as family, pets, cars and hobbies made it easier for me to remember mental models and syntax.

I've also kept them deliberately short so that they are digestible, although a few tips have crept longer than I'd like, but the aim is something you can absorb in 30 seconds, not a mini article.

Is the code the best? No. It's messy and pretty amateur. But I'll look back in a year with broader knowledge and a different approach, and maybe one day completely re-write it.

So far I have nearly 80 JavaScript tips. I've since moved on to React, so that section will grow. I tend to use it in spare moments, mainly early morning or late at night, which is why I went dark mode first.

Check it out [here](https://flashcards-orcin-nine.vercel.app/) (best experienced on mobile).
